## PR 2 — `phase-desktop-drawer`

### Goal

At `≥md` (768px+), opening the hamburger drawer reveals a **cascading
multi-pane** layout: clicking a parent category opens its children to
the right of the current pane instead of replacing it. Mobile keeps the
current stack/push behaviour.

Reference: tools.no's hamburger drawer.

### Locked decisions

- **Click-driven, not hover-driven.** Matches the existing state
  machine; hover-driven mega menus are accessibility-fussy.
- **Mobile (< md) keeps stack/push.** The cascade pattern requires
  width that small viewports don't have.
- **Up to 3 panes side-by-side.** Root + 2 deep. 3 × 280px = 840px,
  comfortable on 1280px viewport.
- **Active parent in each pane is highlighted** so the visual hierarchy
  is unambiguous.
- **No back button on desktop** — visible parent context replaces it.
- **Close button** stays top-right of the leftmost pane.

### File touched

Single file: `src/components/layout/CategoryDrawer.tsx`.

### Implementation outline

The existing `stack` state model already supports this — only the
render layer changes.

1. **State change** — the click handler at depth N now truncates the
   stack at N before pushing the new pane (so a sibling click in pane 1
   collapses any open pane 2-3):

   ```ts
   function pushAt(depth: number, pane: Pane) {
     setStack(s => [...s.slice(0, depth), pane]);
   }
   ```

   On mobile, `depth` is always `stack.length`, so behaviour unchanged.

2. **Render branch**:
   ```tsx
   <aside className="relative flex h-full bg-white shadow-xl">
     {/* Mobile: single 360px pane (current behaviour) */}
     <div className="md:hidden flex flex-col h-full w-full max-w-[360px]">
       {topPane === null
         ? <RootPane onPick={(p) => pushAt(0, p)} />
         : <SubPane pane={topPane} onBack={popPane} />}
     </div>

     {/* Desktop: all panes visible side-by-side */}
     <div className="hidden md:flex h-full">
       <RootPane
         width="280px"
         onPick={(p) => pushAt(0, p)}
         activeChildKey={paneKey(stack[0])}
       />
       {stack.map((pane, i) => (
         <SubPane
           key={i}
           pane={pane}
           width="280px"
           onPick={(child) => pushAt(i + 1, child)}
           activeChildKey={paneKey(stack[i + 1])}
         />
       ))}
     </div>
   </aside>
   ```

3. **Active highlight** — each pane needs to know which of its children
   is "currently expanded" so it can render that row with a different
   background. Helper `paneKey()` returns a stable identifier from a
   Pane object (e.g. node id for categories, "machines" for machines,
   "services" for services).

4. **Close behaviour** — clicking a leaf calls `Link` href; route
   change fires the existing pathname effect that closes the drawer.
   Clicking the close button calls `close()` from the Zustand store.

5. **No layout change for the open trigger** — `HamburgerButton` still
   calls `useDrawerStore.getState().open()`.

### Gates + smoke

Same gates as PR 1. Smoke on desktop:
- Open hamburger → root pane left
- Click "Produkter" → second pane appears to the right, root stays
- Click "Skuffer" in pane 2 → third pane appears, both predecessors stay
- Click "Maskiner" in root → pane 2 (Produkter children) and pane 3
  collapse, "Maskiner" pane appears
- Click a leaf → drawer closes, navigation happens
- Close button → drawer closes

Smoke on mobile (Chrome DevTools mobile emulation):
- Behaviour identical to today

### Estimated time

30 minutes. Single file edit, no new dependencies.
