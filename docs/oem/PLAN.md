# OEM Parts Project — Master Plan

**Last updated:** 2026-06-26

> Sub-project of the IndustriParts main repo. OEM-catalog data (Machine,
> Revision, Diagram, Part, PartLine, …) lives in its own Supabase project
> `rtzcrngduscrhgozrojv` under the `BojoIndAI1` org. The Dyvika storefront
> reads it via a second Prisma client (`src/lib/oem-db.ts`) — no HTTP layer
> between them.

## Status legend

🟢 done · 🟡 partial / in flight · 🔴 not started · ⏸ paused / deferred

## Strategy

A three-tier data hierarchy:

| Tier | What | Source(s) | When used |
|---|---|---|---|
| **1** | Factory BOM data — machines, revisions, diagrams, part lines | eParts API + factory parts-book PDFs | Primary source for any machine where eParts publishes a BOM |
| **2** | BOM fill for big-equipment | LS Engineers (`lsengineers.co.uk`) — they expose BOM-style diagrams for excavators/telehandlers/wheel loaders that eParts has empty | Only for machines where tier 1 came up empty |
| **3** | Enrichment-only — spares without a diagram | Neyer (45K SKUs with descriptions + images), DHS (381K compat rows), LS Engineers listings | For parts that have no factory BOM appearance (aftermarket, consumables, service kits, sealing rings, …) |

Decision rule: ingest tier N only after tier N-1 is complete, so we know
the real gap. Stub Parts (Part rows for SKUs with no BOM appearance) get
created at the very end of tier 3, *only* for SKUs that nothing in tiers
1+2 covers.
